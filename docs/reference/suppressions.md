# Suppressions

Suppressions are source comments for approved exceptions to a `konpy` rule. They are intentionally visible: suppressed findings are still counted in summaries, included in JSON output, and can be listed with `--show-suppressed`.

Prefer fixing the code or changing the rule. Use a suppression only when the rule is correct in general but intentionally does not apply to a specific line or file.

## Grammar

Line-level suppression:

```py
# konpy: ignore[rule-name]
value = legacy_call()  # konpy: ignore[rule-name]
# konpy: ignore[rule-a, rule-b] -- approved legacy API
```

File-level suppression:

```py
# konpy: ignore-file[rule-name]
# konpy: ignore-file[rule-a, rule-b] -- generated file
```

Exact shape:

```text
# konpy: <directive>[<rule-list>][ -- <reason>]
```

Rules:

- `<directive>` is exactly `ignore` or `ignore-file`.
- The bracketed rule list is mandatory.
- The rule list is comma-separated.
- Whitespace around commas is allowed.
- Rule names must be lowercase convention labels using letters, digits, and `-`.
- The optional reason begins with literal ` -- `.
- Reasons are free text and are strongly recommended for human review.

## Rule names

Suppression rule names match the diagnostic's `conventionName`, not the predicate name.

For example, this config emits diagnostics labeled `service-docstrings`:

```json
{
  "name": "service-docstrings",
  "paths": "src/service.py",
  "must": {
    "haveDocstrings": true
  }
}
```

Suppress it with:

```py
# konpy: ignore[service-docstrings] -- legacy public API
def old_handler():
    return 1
```

Do **not** use the predicate key:

```py
# Wrong: this does not suppress service-docstrings
# konpy: ignore[have-docstrings]
def old_handler():
    return 1
```

Unused-code diagnostics use the built-in convention label `unused-code`:

```py
# konpy: ignore[unused-code] -- imported dynamically by plugin loader
def register_plugin():
    return None
```

## Line-level suppressions

`ignore[...]` applies only to diagnostics with a line anchor.

It matches:

1. a suppression comment on the same physical line as the diagnostic; or
2. a suppression comment on the immediately preceding physical line.

Examples:

```py
def legacy(value):  # konpy: ignore[annotations] -- third-party callback shape
    return value
```

```py
# konpy: ignore[annotations] -- third-party callback shape
def legacy(value):
    return value
```

The previous-line form is intentionally strict: it does not skip blank lines or intervening comments. This keeps suppressions local and prevents a comment from accidentally silencing later code.

Line-level suppressions do not suppress file-level diagnostics where no line is available, such as missing paired files or missing required files.

## File-level suppressions

`ignore-file[...]` applies to any diagnostic in the same file, including diagnostics without a line anchor.

File-level suppressions must appear before the first non-blank, non-comment code line:

```py
# Generated by upstream schema compiler.
# konpy: ignore-file[paired-tests] -- generated module has no direct test
VALUE = 1
```

This placement rule keeps broad exceptions prominent and easy to audit. A file-level suppression after code is reported as an invalid suppression warning and is not applied.

Use `ignore-file` sparingly. Prefer line-level suppressions when the diagnostic has a useful line anchor.

## Visibility

Suppressions are never invisible.

Default and Markdown summaries include suppressed counts:

```text
Checked 3 files in 5ms. No unsuppressed violations found. Suppressed 2 findings.
Checked 3 files in 5ms. Found 1 error and 2 warnings. Suppressed 3 findings.
```

Use `--show-suppressed` to list suppressed diagnostics in human-readable formats:

```bash
konpy check --show-suppressed
```

Default output includes a section like:

```text
Suppressed diagnostics:
src/service.py
  4  suppressed warning  Definition "legacy" is only referenced by tests  [unused-code]  (suppressed by line 3: legacy API)
```

GitHub output emits suppressed diagnostics as notices only when `--show-suppressed` is passed.

JSON output always includes suppressed diagnostics because machine consumers should not lose audit information.

## JSON shape

`--format json` returns an object:

```json
{
  "diagnostics": [],
  "suppressed": [
    {
      "severity": "warning",
      "conventionName": "unused-code",
      "filePath": "src/service.py",
      "predicateName": "unusedCode.dead",
      "message": "Unused definition \"legacy\" is never referenced",
      "line": 4,
      "suppressedBy": {
        "kind": "ignore",
        "filePath": "src/service.py",
        "line": 3,
        "reason": "legacy API"
      }
    }
  ],
  "summary": {
    "filesChecked": 1,
    "errors": 0,
    "warnings": 0,
    "suppressed": 1,
    "durationMs": 5.0
  }
}
```

The `diagnostics` array contains unsuppressed diagnostics only. Suppressed diagnostics do not affect the exit code.

## Unknown, invalid, and unused suppressions

Suppression hygiene warnings are on by default:

| Case | Message |
| --- | --- |
| Missing or empty bracketed rule list | `Invalid suppression comment: bracketed rule list is required` |
| Invalid rule name | `Invalid suppression rule name "RuleName"` |
| File-level suppression after code | `File-level suppression for "rule-name" must appear before the first code line` |
| Unknown rule label | `Unknown suppression rule "rule-name"` |
| Known rule label that did not suppress anything | `Unused suppression for "rule-name"` |

These diagnostics use:

```text
severity: warning
conventionName: suppressions
```

They count as warnings and fail the command when `--error-on-warnings` is set.

When `--diagnostic-level error` is used, suppression hygiene warnings are skipped along with other warning-level checks.

## Examples

### Suppress a `must` diagnostic

```py
# konpy: ignore[service-docstrings] -- legacy API kept stable for clients
def old_handler():
    return 1
```

### Suppress a `mustNot` diagnostic

```py
# konpy: ignore-file[no-debug-content] -- debug fixture is intentionally checked in
DEBUG_ONLY = True
```

### Suppress unused-code

```py
def dynamic_hook():  # konpy: ignore[unused-code] -- loaded by framework string
    return None
```

### Suppress a file-level diagnostic

```py
# konpy: ignore-file[paired-tests] -- generated module has no direct test
GENERATED = True
```

## AI agents

AI agents must not add suppressions without explicit human approval.

By default, agents should:

1. fix the underlying violation when the fix is clear;
2. ask whether the rule or code should change when intent is unclear; and
3. avoid suppressions unless a human explicitly approves the exception.

If a human approves a suppression, agents should:

- use the narrowest possible suppression;
- prefer `ignore[...]` over `ignore-file[...]` when the diagnostic has a line anchor;
- include a reason after ` -- `;
- use the diagnostic `conventionName`, not the predicate name; and
- leave suppressed findings visible in review output.

Good:

```py
# konpy: ignore[unused-code] -- approved by maintainer: loaded by external plugin registry
def register_external_plugin():
    return None
```

Bad:

```py
# No explicit human approval, no reason, too broad.
# konpy: ignore-file[unused-code]
```
